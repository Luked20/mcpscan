# MCP007 — Unpinned MCP server provenance

**Severity:** medium · **Confidence:** high · **OWASP MCP:** `MCP04:2025 – Software Supply Chain Attacks & Dependency Tampering`

## The risk

An MCP server entry in a client config is an instruction to run code. Where that code comes from is part of your threat model, and three shapes make the answer "whatever the network serves at the moment the agent starts":

- **A package fetched at run time with no exact version.** `npx -y some-mcp` and `npx -y some-mcp@latest` resolve fresh on every launch. The maintainer you audited can publish a new version, or lose their npm account, and your agent picks it up without a diff, a review, or a prompt.
- **A script piped straight into a shell.** `curl … | sh` executes whatever the host returns, right now. The content you read in a browser and the content served to your machine need not be the same.
- **Plaintext HTTP.** `http://` exposes the traffic and any bearer token to anyone on the path, and lets them modify the tool definitions the model receives.

This is not a hypothetical for MCP specifically: a server config is usually committed, rarely re-reviewed, and grants the agent whatever the server exposes.

## Vulnerable example

```json
{
  "mcpServers": {
    "files":  { "command": "npx", "args": ["-y", "some-mcp@latest"] },
    "setup":  { "command": "sh", "args": ["-c", "curl -fsSL https://get.example.com/i.sh | sh"] },
    "remote": { "url": "http://internal.example.com/mcp" }
  }
}
```

## Clean example

```json
{
  "mcpServers": {
    "files":  { "command": "npx", "args": ["-y", "some-mcp@1.4.2"] },
    "local":  { "command": "node", "args": ["./dist/server.js"] },
    "remote": { "url": "https://api.example.com/mcp" }
  }
}
```

## What this rule does NOT flag

- **An exact version pin** — `some-mcp@1.4.2`, `@acme/some-mcp@2.0.1`, `some-mcp@3.0.0-beta.1`. A prerelease is still a pin.
- **A local binary** — `command: "node"` with `args: ["./dist/server.js"]`. Nothing is fetched.
- **A package whose name merely contains the word "latest"** — `latest-news-mcp@2.0.1` is pinned and does not fire.
- **`https://` URLs**, including SSE endpoints.
- **A pipe that is not into a shell** — `cat data.json | jq .tools`.

## How to fix

**Unpinned fetch:** pin the exact version, or install the server as a project dependency and point `command` at the local binary:

```json
{ "command": "node", "args": ["./node_modules/.bin/some-mcp"] }
```

Commit a lockfile so the transitive dependency tree is pinned too — pinning the top-level package alone still leaves its dependencies floating.

**Pipe to shell:** download the script, read it, pin it by commit SHA, and run the verified copy. For releases, verify the published checksum.

**Plaintext HTTP:** use `https://`. If the server is local, prefer the stdio transport and skip HTTP entirely.
