# MCP009 — Credential hardcoded in MCP server configuration

**Severity:** high · **Confidence:** high · **OWASP MCP:** `MCP01:2025 – Token Mismanagement & Secret Exposure`

## The risk

An MCP client config is a file people commit. A credential written literally into an `env` block is not a secret any more the moment that commit is pushed — it is readable by everyone with repository access, it survives in the git history after you "fix" it, and it is indexed by anyone scraping public repositories for exactly this pattern.

The distinguishing feature of this mistake is that it looks fine locally. The server works, the token is right there, nothing complains. The exposure is entirely in the file's future.

## Vulnerable example

```json
{
  "mcpServers": {
    "github": {
      "command": "node",
      "args": ["./gh.js"],
      "env": { "GITHUB_TOKEN": "ghp_AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA" }
    }
  }
}
```

## Clean example

```json
{
  "mcpServers": {
    "github": {
      "command": "node",
      "args": ["./gh.js"],
      "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
```

## What this rule does NOT flag

- **Environment references** — `${GITHUB_TOKEN}`, `$GITHUB_TOKEN`, `${env:TOKEN}`. These are the correct pattern, not the bug.
- **Placeholders** — `your-token-here`, `<YOUR_KEY>`, `changeme`, `xxx`, and similar fill-me-in values.
- **Ordinary settings** — `LOG_LEVEL=debug`, `PORT=8080`, `REGION=us-east-1`.
- **Empty values.**
- Anything that does not match a known credential shape. The rule keys on distinctive, low-collision prefixes (`sk-`, `sk-ant-`, `ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`, `AKIA`, `xoxb-`, a three-segment `eyJ…` JWT) rather than guessing from entropy, which is what keeps it quiet.

## The finding never contains the secret

`evidence` shows at most the first four characters and the last two: `GITHUB_TOKEN=ghp_…AB`.

This is deliberate and is enforced by a test. A finding travels into CI logs, terminal scrollback, and the SARIF artifact that frequently gets committed. A scanner that echoes the credential it found has copied it to three new places and made the problem worse than it was.

## How to fix

1. Replace the value with a reference: `"GITHUB_TOKEN": "${GITHUB_TOKEN}"`, and supply the real value from your shell environment or a secret manager.
2. **Revoke and reissue the credential.** This step is not optional and it is the one people skip. Moving the value now does nothing about the commit that introduced it — the token has been readable in the repository's history since that moment, and rewriting history does not help if the repository was ever cloned, forked, or mirrored.

Treat any credential that reached a commit as compromised, even in a private repository.

## How to suppress

```
// mcpscan-disable-next-line MCP009 -- test double, not a live credential
```

A reason after `--` is required. A suppression with no reason is ignored and reported instead.

If you are suppressing this rule, check that the value really is inert. A "test" token that still authenticates is a live credential.
