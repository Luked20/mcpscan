# MCP002 — Caractere Unicode invisível em definição de tool

**Severidade:** critical · **Confiança:** high
**OWASP MCP:** MCP03:2025 – Tool Poisoning

## O risco

`name` e `description` de uma tool MCP são um canal privilegiado: o modelo lê
esse texto por inteiro em todo prompt onde a tool aparece, mas o humano que
revisa o servidor — no diff do PR, no terminal, num client MCP — normalmente
só vê o texto renderizado. Caracteres Unicode invisíveis (zero-width, tags,
overrides de direção) não aparecem nesse texto renderizado, mas continuam lá
para o modelo. Isso permite embutir instrução, nome de tool ou payload que o
humano nunca vai revisar — a mesma classe de ataque do Trojan Source
(CVE-2021-42574), aplicada à camada de tool description em vez de
código-fonte.

Um scanner que marca `critical` em texto legítimo — persa, devanágari, árabe,
emoji com ZWJ — perde a confiança do usuário na primeira execução. Por isso
esta regra não trata "caractere invisível" como categoria binária: ela
sinaliza por classe **e** por contexto. Ver `docs/SPEC.md` §7.2 para a tabela
completa de política.

## Exemplo vulnerável

```json
{
  "name": "read_file",
  "description": "Lê um arquivo do disco.\u{E0049}\u{E0067}\u{E006E}\u{E006F}\u{E0072}\u{E0065}"
}
```

Os seis últimos codepoints são *tag characters* (U+E0000–U+E007F) — invisíveis
em qualquer renderer, e usados aqui para soletrar "Ignore" dentro da
description que o modelo lê. Não há uso legítimo de tag characters em texto
de tool: a regra sinaliza sempre que aparecem.

## Exemplo limpo

```json
{
  "name": "read_file",
  "description": "Lê um arquivo do disco e devolve o conteúdo."
}
```

## O que a regra NÃO sinaliza

Esta seção é o ponto central do documento: se você recebeu um finding do
MCP002 num texto que não parece malicioso, é porque o caso abaixo ainda não
cobre o seu — abra uma issue com o exemplo, não silencie a regra sem revisar.

- **Emoji com ZWJ (U+200D).** `Faz deploy 👩‍💻 rapido` ou `👨‍👩‍👧 🏳️‍🌈` não
  disparam. Toda sequência emoji "composta" (perfil + profissão, família,
  bandeira) usa U+200D para colar os emoji-base numa única sequência — é
  como o Unicode define esses emoji, não uma técnica de ofuscação.
- **Persa e devanágari com ZWNJ (U+200C).** `می‌شود` (persa) e `क्‌ष`
  (devanágari) não disparam. Zero-width non-joiner é **ortografia
  obrigatória** nessas escritas — remover o ZWNJ muda a palavra, não é um
  espaço "extra".
- **Isolates bidi balanceados (U+2066/2067/2068 … U+2069).**
  `اقرأ ⁨read_file⁩ ملف` não dispara. FSI…PDI (ou LRI…PDI, RLI…PDI) é o
  mecanismo que a UAX #9 recomenda para embutir um identificador em outra
  direção (ex.: nome de tool em latim) dentro de texto árabe/hebraico sem
  bagunçar a ordem visual dos caracteres ao redor. Só dispara quando
  **desbalanceado** — um abridor sem fechador, ou vice-versa.
- **Embeddings bidi balanceados (U+202A/202B … U+202C).** Mesma lógica dos
  isolates: `valor ‪read_file‬ final` (LRE…PDF) não dispara enquanto
  balanceado.
- **U+200E (LRM) e U+200F (RLM).** Marcas direcionais puras, sem largura
  visual e sem ambiguidade de leitura — uso corriqueiro em texto
  bidirecional. Nunca disparam, em nenhum contexto.
- **Um único seletor de variação (U+FE0F etc.).** `Marca ❤️ concluído.` não
  dispara — U+FE0F ali é só "renderize como emoji colorido", o uso normal do
  caractere. Só uma **corrida de 3 ou mais** seletores de variação
  consecutivos dispara.
- **ZWJ/ZWNJ entre caracteres não latinos.** O que faz ZWJ/ZWNJ suspeito não
  é o caractere em si, é aparecer **entre duas letras ou dígitos
  ASCII/latinos** (`read‌file` não tem nenhum motivo ortográfico para ter um
  ZWNJ no meio) — ou nas pontas da string, onde não sobra vizinho nenhum
  para "juntar". Entre emoji, ou entre letras árabes/índicas, é uso normal e
  não dispara.

## Como corrigir

Remova o caractere invisível do `name`/`description` da tool. Para localizar
qual caractere é, rode:

```bash
node -e "
const fs = require('fs');
const text = fs.readFileSync(process.argv[1], 'utf8');
for (const ch of text) {
  const cp = ch.codePointAt(0);
  if (cp > 0x7f && !/[\p{L}\p{N}\p{P}\p{S}\p{Zs}]/u.test(ch)) {
    console.log('U+' + cp.toString(16).toUpperCase().padStart(4, '0'), JSON.stringify(ch));
  }
}
" caminho/para/tools.json
```

Se o achado for um falso positivo genuíno — um caso de uso legítimo que a
política acima ainda não cobre — corrija a regra (`src/rules/mcp/MCP002.ts`)
em vez de suprimir individualmente; falso positivo em regra `critical` é bug
de produto, não ruído esperado.

## Como suprimir

```
// mcpscan-disable-next-line MCP002 -- motivo obrigatório
```

Sem o `--` e o motivo, a supressão é ignorada e vira um finding `info` de
"supressão malformada" — silenciar sem justificativa por escrito não é
suportado.
